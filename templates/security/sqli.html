📖 SQL Injection — Educational Briefing CWE-89 / OWASP A03:2021
1. What is it?

SQL Injection (SQLi) is a code-injection vulnerability where malicious SQL commands are inserted into data entry fields to manipulate database query execution.

2. Why does it happen? (Root Cause)

It occurs when user input is concatenated directly into SQL command strings instead of being passed as separate data parameters.

3. Impact

Unauthorized data dumping, authentication bypass, record alteration, or extraction of confidential case information.

4. Prevention (Mitigation)

Parameterized queries (prepared statements via SQLite ? placeholders), which force the database engine to treat inputs strictly as literal values.

🔍 Code-Level Before vs. After Comparison
❌ VULNERABLE: Direct String Formatting
# Flawed approach: user input breaks out of SQL string
query = f"SELECT * FROM cases WHERE code = '{user_input}'"
cursor.execute(query)  # Vulnerable to injection!
✅ SECURE: Parameterized Prepared Statement
# Secure approach: SQLite engine compiles query structure first
query = "SELECT * FROM cases WHERE code = ?"
cursor.execute(query, (user_input,))  # Fully safe!
