📖 Cross-Site Request Forgery (CSRF) — Educational Briefing CWE-352 / OWASP A01:2021
1. What is it?

CSRF is an attack that tricks an authenticated victim's browser into sending an unwanted state-changing HTTP request to a vulnerable application.

2. Why does it happen? (Root Cause)

Web browsers automatically include session cookies with every request sent to a domain. Without an origin or token check, the server cannot tell if the request was submitted intentionally by the user or forged by an external site.

3. Impact

Unauthorized profile updates, email changes, password resets, or forensic data modifications performed without operator knowledge.

4. Prevention (Mitigation)

Cryptographic Synchronizer Tokens (CSRF tokens). A random, unpredictable token stored in the server session is verified on every state-changing POST request.

🔍 Defense Mechanism: How Synchronizer Tokens Stop CSRF

An attacker site can force a browser to send requests to an internal web application with cookies, but because of the Same-Origin Policy (SOP), the attacker site cannot read the HTML or JavaScript of the target domain. Therefore, the attacker cannot steal or guess the unique CSRF token stored inside the user's session: 

# Server-side verification logic in app.py:
submitted_token = request.form.get('csrf_token')
session_token = session.get('csrf_token')

if not submitted_token or submitted_token != session_token:
    abort(400, "CSRF validation failed: State change rejected.")
